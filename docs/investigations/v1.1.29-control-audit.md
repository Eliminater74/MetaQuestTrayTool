# v1.1.29 control audit — 2026-09-08

## Scope and evidence

Reviewed shell pages, dialogs, tray/hotkey/voice routing, model values, saved-value loading, registry/CLI/ADB command construction, and existing session guards. The table below inventories every named input in the XAML view tree, together with each view's distinct declarative handlers. Programmatic handlers were traced in code-behind. Build validation resolves XAML event handlers; it does not prove physical device behavior.

The audit is **not a claim that every Meta/Windows/headset action was physically exercised**. Link/ODT observations are recorded in [issue-4-link-registry.md](issue-4-link-registry.md). Ordinary regression tests use isolated state. No destructive/reset/startup-registration/power/audio/device action was executed merely to test a button.

## Repairs completed and committed by stage

- Corrected Link sharpening mapping, width-alias precedence, read-back verification and Read Live controls in the preceding investigation.
- Fixed FOV JSON migration: the serialized legacy single-value property previously overwrote a distinct vertical value. Modern axes now win regardless of property order, and legacy-only files still populate both axes.
- Restoring FOV to 1/1 now sends the explicit CLI command. Profile/global-default editors expose both axes; all three editors reject NaN/infinity/out-of-range values.
- Captured wireless connect/pair and Send text input on the WPF thread before background ADB work; completed UI cleanup on the WPF thread.
- Preserved custom SS/bitrate/width/offset values across the shell and dialogs. Null profile inheritance remains distinct from explicit zero. Negative dynamic offsets survive unrelated edits/apply.
- Replaced HUD enum casts with explicit CLI mapping: Performance/headroom summary=1, App Render Timing=3, Compositor Render Timing=4, ASW=6. Saved enum numbers are unchanged. Version keeps legacy 5 with a result qualification because this ODT does not expose its label.
- Corrected hints that promised unverified Mobile ASW/capture behavior. Existing legacy features remain available.

## Installed CLI / ODT observations

`help service`, `help service set-client-fov-tan-angle-multiplier`, `help service set-offset-mip-bias-on-all-layers`, and `help perfhud set-mode` were read from the installation discovered through the existing Oculus registry location. No installation path was added to application source.

Sequential CLI HUD writes followed by ODT observation showed 2=Latency Timing, 3=App Render Timing, 4=Compositor Render Timing, and 6=Async-SpaceWarp Stats. Mode 5 produced a blank selector label; this does not prove the legacy Version runtime mode is unsupported. The full selector lists Performance Summary, Latency Timing, App Render Timing, Compositor Render Timing, Async-SpaceWarp Stats, Oculus Link, Oculus Link Detail, and Network Guardian Info. Unexposed newer options were not added speculatively.

Diagnostic ODT instances were closed, and `perfhud reset` restored the original disabled HUD state. Link registry overrides remain at the previously restored baseline. The original tester-specific bitrate failure is still not reproduced; issue #4 must not be declared fully resolved on the strength of local tests.
